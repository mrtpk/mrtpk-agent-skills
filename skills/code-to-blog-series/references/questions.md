# Questions for the author

Ask these before you build. Give a proposed default for each. Ask in groups of at most 4.

## The project

1. What was the system? Who wrote which part? (Do not assume that the author wrote all of it.)
2. In which direction did the design go? (For example: the code was the spec, and another team implemented it. Or: the code modelled an existing system.)
3. What were the external constraints? (Hardware limits, latency budgets, memory, APIs.)
4. Which results does the author remember? Which numbers are lost?
5. Who guided the work? Who must get credit, and how? (For example an "Acknowledgement" block with a profile link.)

## Publishing

6. Which names must not appear in public? (Product, hardware, internal project, organisation names in old URLs.)
7. May the employer be named?
8. Is there an NDA? Does the author want to say that they have the code? (Default: no. Describe the design from memory and from new scripts.)
9. May the posts give result numbers (accuracy, speed)? (Default: only numbers that a script in the post makes.)
10. Tone about old gaps? (Default: soft. "Gaps" and "refinements", not "bugs" or "mistakes".)
11. "I" or "we"? (Default: "we" for team work, "I" only for the author's own part and for the new analysis.)

## Form

12. Which blog repo, and does it have a style guide? (Default: use its `STYLE.md` when it exists; else `writing.md` of this skill.)
13. One long post or a series? (Default: a series for more than about 3000 words.)
14. A prequel for the basics? (For example a rewrite of an earlier answer or note by the author.)
15. Series name and title format? (Default: "<Series> - Part N: <topic>".)
16. LinkedIn companions?
17. Git: author name and email, one commit per post, a branch, push or not?
18. Attended or unattended run?
